# LegacyStoreRelay

Указатель на репозитории с приложениями для **Legacy Store** — магазина `.ipa`
для jailbreak-устройств на iOS 5 и 6.

Сам по себе этот репозиторий не хранит ни одного приложения. Он хранит **список
мест, где они лежат**, и один склеенный каталог, уже разобранный за устройство.

```
              ┌─────────────────────┐
              │  LegacyStoreRelay   │   version.txt      ~100 байт
              │     (этот репо)     │   relay.tsv        список шардов
              └──────────┬──────────┘   catalog-all.tsv  склейка всех
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
  LegacyStoreDC1   LegacyStoreDC2   LegacyStoreDC3…
  catalog.tsv      catalog.tsv      catalog.tsv
  icons/           icons/           icons/
  apps/            apps/            apps/
```

## Зачем шарды

GitVerse Pages ограничивает артефакт сборки 500 МБ. Один репозиторий на всё
однажды упрётся в этот потолок, и переезжать придётся всем каталогом сразу.
Поэтому заполненный шард помечается `frozen`, заводится следующий, а
`catalog-all.tsv` пересобирается — на устройстве при этом не меняется ничего.

## Зачем предпарсенный каталог

Устройство — iPhone 4 или iPad 3: 512 МБ памяти и jetsam, который убивает
процесс за лишний аппетит. Оно не должно обходить шарды по одному, склеивать их
и разбирать JSON. Порядок такой:

1. качает `version.txt` (сотня байт) и сравнивает `generation` с сохранённым;
2. если не изменилось — не делает больше ничего;
3. если изменилось — качает `catalog-all.tsv` одним куском и кладёт рядом с
   основным каталогом.

К шардам устройство обращается только за иконкой и за самим `.ipa` — то есть
тогда, когда пользователь на них смотрит.

Форматы описаны в [SCHEMA.md](SCHEMA.md).

## Где лежат сами .ipa

**Не здесь.** В каталоге лежит ссылка автора и `sha256` файла. Это сознательно:
хранение чужих бинарей стоило бы места и превращало бы указатель в файлопомойку,
а лимит Pages кончился бы на первом десятке приложений.

`sha256` в каталоге — не украшение: файл лежит у автора, ссылка может протухнуть
или подмениться, и клиент обязан заметить это **до** установки.

Маленькое (до ~5 МБ) можно класть прямо в шард, в `files/` — тогда ссылка ведёт
на Pages.

## Как добавить приложение

1. Заводится issue по шаблону: `bundleId`, имя, версия, минимальная iOS, ссылка
   на `.ipa`.
2. Модератор ставит метку `approved`.
3. `python3 tools/build_relay.py` — скачивает файл, **проверяет его**:
   настоящий ли это zip, есть ли внутри `Payload/*.app/Info.plist`, совпадает ли
   `bundleId` с заявленным, есть ли срез `armv7`, не выше ли `MinimumOSVersion`
   целевой. Затем считает `sha256`, пишет карточку в шард и пересобирает
   `catalog-all.tsv` и `version.txt`.
4. `git push` — Pages раскатывает сам.

Проверки структурные. Они ловят битый архив, подделку `bundleId` и сборку не под
ту архитектуру — но не отвечают на вопрос, что этот бинарь делает. Единственный
настоящий фильтр здесь — модератор.

## Чего здесь нет и не будет

**Токена записи в приложении.** Магазин из этого репозитория только читает.
Ключ, зашитый в `.deb`, достаётся из него за одну команду — а значит, право
писать в каталог получил бы каждый, кто скачал магазин.
